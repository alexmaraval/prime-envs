# bird

Multi-turn BIRD-SQL environment for Prime/Verifiers.

The agent solves a natural-language question by inspecting the active SQLite database, dry-running candidate answers with `suggest`, submitting final SQL with `submit`, and then calling `terminate`. Rewards are deterministic execution rewards:

- `+0.05` when the submitted final SQL executes successfully.
- `+1.0` when the submitted final SQL result matches the gold SQL result. The default `scoring_mode="official"` follows the BIRD evaluator's set equality over result rows; `scoring_mode="strict"` is available as a duplicate/order-sensitive diagnostic.
- Maximum reward is `1.05`.

Oracle BIRD evidence is included by default. Set `include_evidence=false` to run no-oracle prompts closer to the single-model track.

## Data

The BIRD SQLite assets are too large to package with the environment. This package expects the data directory to be available locally or mounted remotely.

Resolution order:

1. `bird_data_dir` environment argument.
2. `BIRD_DATA_DIR` environment variable.
3. Package-local `.data/` when developing in this workspace.

Expected layout:

```text
.data/
  train/
    train.json
    train_tables.json
    train_databases/<db_id>/<db_id>.sqlite
  dev_20240627/
    dev.json
    dev_tables.json
    dev_tied_append.json
    dev_databases/<db_id>/<db_id>.sqlite
```

Optional cached metadata can live in:

```text
.data/metadata/train_filtered.json
.data/metadata/bird_mini_dev_sqlite.json
```

Use `scripts/prepare_data.py` to verify the layout or cache small Hugging Face metadata. It does not download the large database assets during environment loading.

## Describe Profiles

`describe` lazily maintains deterministic database profiles under:

```text
.data/metadata/descriptors/<train|dev>/<db_id>.profile.json
```

The first `describe` call for a database creates the profile if it is missing. Later calls reuse it. When `describe_model` is configured, `describe` uses the cached profile to produce a fresh LLM-written description for the requested database, table, or column without saving that prose.

```bash
uv run python scripts/generate_descriptors.py --data-dir .data --splits train dev
```

The script is optional and only prewarms profile caches. Runtime descriptions are still generated by the `describe` tool itself. `describe("database")` requests a whole-database description; table and `table.column` targets continue to work as before.

## SQL Result Cache

Gold SQL execution results are cached across eval runs and dashboard renders. By default, the cache lives under:

```text
.data/.cache/sql_results/
```

Set `BIRD_SQL_RESULT_CACHE_DIR` or pass `sql_result_cache_dir` to use a different shared cache directory. Cache files include columns, full result rows, original execution time in `elapsed_ms`, database fingerprint, and SQL text. The environment uses cached gold results during EX reward calculation, and `scripts/visualize_rollouts.py` uses the same cache for gold output previews.

## Tools

| Tool | Purpose |
| --- | --- |
| `describe(targets, sample_rows=None)` | Return schema/profile context plus an optional runtime LLM description for `database`, tables, or `table.column` targets. Optional samples are capped by `max_describe_sample_rows`. |
| `explore(sql)` | Execute one read-only `SELECT`/`WITH` query with row and timeout limits. |
| `suggest(sql)` | Dry-run a candidate final SQL query and return limited output without revealing correctness. |
| `submit(sql)` | Execute the final SQL, return limited output or an error, and record it for scoring only if execution succeeds. |
| `terminate()` | Finish the rollout after `submit` and trigger scoring. |

## Quickstart

From this directory:

```bash
prime env install bird
prime eval run bird -m gpt-4.1-mini -n 5 -a '{"split":"test","eval_split":"test","max_turns":8}'
```

From the repository root:

```bash
BIRD_DATA_DIR=/Users/alexandremaraval/Documents/Projects/prime-envs/environments/bird/.data \
uv run prime eval run bird \
  -m gpt-4.1-mini \
  -n 5 \
  -a '{"split":"test","eval_split":"test","max_turns":8}'
```

## Trajectory Dashboard

Generate a static HTML dashboard from any eval `results.jsonl`:

```bash
python scripts/visualize_rollouts.py outputs/evals/bird--gpt-4.1-nano/95625562/results.jsonl
```

The generated dashboard appears next to the input as `results_dashboard.html`. It includes run-level metrics, trajectory filters, executed submitted-versus-gold output previews, final SQL versus gold SQL, explored query summaries, tool-call sequences, structured tool outputs, failure tags, a trajectory postmortem, and the full prompt/completion timeline.

Export a Prime eval result to the official BIRD evaluator prediction format:

```bash
python scripts/export_official_predictions.py outputs/evals/bird--gpt-4.1-nano/95625562/results.jsonl
```

This writes `predict_dev.json`, where each value has the official `SQL<TAB>----- bird -----<TAB>db_id` shape consumed by `bird/llm/src/evaluation.py`.

## Environment Arguments

| Arg | Type | Default | Description |
| --- | --- | --- | --- |
| `split` | `str` | `"train"` | Training dataset source: `train`, `val`, or `test`. |
| `eval_split` | `str` | `"val"` | Evaluation dataset source. |
| `bird_data_dir` | `str \| null` | `null` | Explicit path to BIRD data root. |
| `include_evidence` | `bool` | `true` | Include the BIRD oracle evidence in prompts. |
| `initial_schema_mode` | `str` | `"ddl"` | Initial schema context: `tables`, `ddl`, or `ddl_with_descriptions`. |
| `scoring_mode` | `str` | `"official"` | Result matching mode: BIRD-compatible `official` set equality or diagnostic `strict`. |
| `max_turns` | `int` | `12` | Maximum model turns. |
| `max_describe_sample_rows` | `int` | `3` | Cap for optional samples returned by `describe(sample_rows=...)`. |
| `describe_model` | `str \| null` | `null` | Optional model used inside `describe` to write runtime descriptions from cached profiles. |
| `describe_base_url` | `str \| null` | `null` | Optional OpenAI-compatible endpoint for `describe_model`. |
| `describe_timeout_seconds` | `float \| null` | `30.0` | Optional timeout passed to the runtime description client. |
| `describe_top_values_limit` | `int` | `10` | Frequent-value count stored in cached profiles. |
| `describe_sample_values_limit` | `int` | `5` | Example-value count stored in cached profiles. |
| `describe_large_table_sample_rows` | `int` | `100000` | First-N row cap for profiling large tables; `0` requests full scans. |
| `max_explore_rows` | `int` | `20` | Maximum rows returned by `explore`. |
| `max_explore_seconds` | `float` | `5.0` | Timeout for `explore`. |
| `max_score_seconds` | `float` | `30.0` | Timeout for final SQL and gold SQL execution. |
| `sql_result_cache_dir` | `str \| null` | `null` | Optional override for the shared gold SQL result cache directory. |
| `num_examples` | `int \| null` | `null` | Optional deterministic subset size. |
| `seed` | `int` | `0` | Subset sampling seed. |

## Remote Training

Do not commit the 32G database directory to the Environment Hub. The local workspace keeps it in hidden `.data/` so Prime's source archive skips it. Push only this package code and mount or pre-stage BIRD data on the remote runtime. The remote run should set:

```bash
BIRD_DATA_DIR=/mnt/bird
```

The starter hosted config in `configs/rl/bird-qwen3-4b-instruct.toml` assumes that environment variable is present.
